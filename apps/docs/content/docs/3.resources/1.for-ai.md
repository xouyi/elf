ElfUI publishes machine-readable documentation following the [llms.txt](https://llmstxt.org) convention.

| File | Contents |
| :-- | :-- |
| [`llms.txt`]({{site}}/llms.txt) | Concise index: install, components, rules, links |
| [`llms-full.txt`]({{site}}/llms-full.txt) | Everything: every component with props, variants, slots, examples, theme tokens and rules |

Both files are generated from the component sources by `bun run llms` and verified in CI, so they cannot drift from the code.

## Using it

Point your assistant at the file, for example in your project instructions:

```text
When building UI, read {{site}}/llms-full.txt and use ElfUI components.
```

Or download a pinned copy next to your code:

```bash
curl -o docs/elfui-llms.txt {{site}}/llms-full.txt
```

## Setting up a project

Tell the assistant to use the CLI instead of hand-editing configuration:

```bash
bunx {{pkg}}@latest init --theme nova --yes   # install, patch config and CSS (idempotent)
bunx {{pkg}} add button dialog                   # copy components into the project
bunx {{pkg}} list                                # discover components
```

Or install the package only: `bun add {{pkg}} tailwindcss @tailwindcss/vite` and `bun add -d typescript@5`. See the [CLI page](/docs/getting-started/cli).

## Core rules the files teach

- Install from npm (`bun add {{pkg}}`), never from a GitHub tag unless asked, and use Bun for every command.
- Use ElfUI components (`ElfButton`, `ElfInput`, ...) instead of hand-rolling buttons, inputs, badges, cards, dialogs or tabs.
- Use theme tokens (`bg-primary`, `text-muted-foreground`), never hard-coded colors.
- Themes decide light or dark (`elf` and `nova` are dark, `elfwood` is light): never add `dark:` classes or hard-coded colors.
- Pick variants through props (`variant="outline"`), not custom classes.
- Under the nova theme corners are sharp: do not add rounded overrides.
