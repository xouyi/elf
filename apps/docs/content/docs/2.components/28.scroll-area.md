## Usage

```vue
<script setup lang="ts">
const items = Array.from({ length: 40 }, (_, i) => `Item ${i + 1}`)
</script>

<template>
  <ElfScrollArea label="Inventory list" class="h-72 w-64 rounded-md border">
    <div class="p-4">
      <p v-for="item in items" :key="item">{{ item }}</p>
    </div>
  </ElfScrollArea>
</template>
```

`ElfScrollArea` is built on the Reka UI `ScrollArea` primitive. The browser still scrolls the real element: wheel, touch, trackpad, scroll anchoring and find in page keep working, and only the scrollbars are drawn by the component. Give the area a height or width (a `h-*` or `max-h-*` class) so that it has something to overflow.

| Part | Purpose |
| :-- | :-- |
| `ElfScrollArea` | The root and the scrolling viewport, with one or both scrollbars. Props: `type`, `orientation`, `scrollHideDelay`, `label`, `viewportClass`. |
| `ElfScrollBar` | A single scrollbar. `ElfScrollArea` renders them for you; use it only to build a custom layout. |

| Prop | Values |
| :-- | :-- |
| `type` | `hover` (default, visible while hovering), `scroll` (while scrolling), `auto` (when content overflows) or `always`. |
| `orientation` | `vertical` (default), `horizontal` or `both`. |
| `scrollHideDelay` | Milliseconds before the bar hides for `hover` and `scroll`. |

### Mobile

Touch screens scroll the viewport natively with momentum. The scrollbars are 10px wide and only decoration there; content must not depend on dragging them. Use `type="auto"` when the bars should be visible on small screens.

## Accessibility

- The viewport is a focusable element (`tabindex="0"`), so keyboard users can scroll it; without that, a mouse-only scroll area would be unreachable. It shows a focus ring.
- Pass `label` to expose the viewport as a named `region`, so that a screen reader says what the focus landed on. Without a label it is a plain focusable block.
- The scrollbars are decorative and hidden from assistive technology; scrolling is done with the viewport.
- Do not put a scroll area around content that already has its own focusable scroll, and avoid nesting scroll areas.

| Key | Action |
| :-- | :-- |
| <kbd>Tab</kbd> | Moves focus to the viewport (then on to the focusable content inside it). |
| <kbd>ArrowDown</kbd> / <kbd>ArrowUp</kbd> | Scrolls vertically by a line. |
| <kbd>ArrowRight</kbd> / <kbd>ArrowLeft</kbd> | Scrolls horizontally by a line. |
| <kbd>PageDown</kbd> / <kbd>PageUp</kbd> / <kbd>Space</kbd> | Scrolls by a page. |
| <kbd>Home</kbd> / <kbd>End</kbd> | Scrolls to the top or bottom. |

## Do and don't

| Do | Don't |
| :-- | :-- |
| Give it a fixed or maximum size and a `label`. | Wrap the whole page in one; let the page scroll normally. |
| Use it for lists, code and tables that must scroll inside a panel. | Hide important content that only appears after scrolling without a cue. |
| Keep the scrollbar visible (`type="auto"` or `always`) when users must discover that it scrolls. | Rely on the thumb for touch interaction. |
