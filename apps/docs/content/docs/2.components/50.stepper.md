## Usage

```vue
<template>
  <ElfStepper v-model="step" aria-label="New item">
    <ElfStepperItem :step="1">
      <ElfStepperTrigger>
        <ElfStepperIndicator />
        <ElfStepperTitle>Photo</ElfStepperTitle>
      </ElfStepperTrigger>
      <ElfStepperSeparator />
    </ElfStepperItem>
    <ElfStepperItem :step="2">
      <ElfStepperTrigger>
        <ElfStepperIndicator />
        <ElfStepperTitle>Details</ElfStepperTitle>
      </ElfStepperTrigger>
    </ElfStepperItem>
  </ElfStepper>
</template>
```

`ElfStepper` is built on the Reka UI `Stepper` primitive, which provides the step state, the linear rule, arrow-key navigation and the live announcement. Steps are numbered from 1. The stepper is a header: it does not render step content, so show your form for `step` yourself (for example with `v-if` or `v-show`).

| Part | Purpose |
| :-- | :-- |
| `ElfStepper` | Root. `v-model` (number, 1-based) or `defaultValue`, `orientation`, `linear`. The default slot receives `modelValue`, `totalSteps`, `goToStep`, `nextStep`, `prevStep`, `hasNext`, `hasPrev`, `isFirstStep` and `isLastStep`. |
| `ElfStepperItem` | One step. Required `step`; optional `disabled` and `completed` (forces the completed state). Its `data-state` is `completed`, `active` or `inactive`. |
| `ElfStepperTrigger` | The button that selects the step. It is named by `ElfStepperTitle`. |
| `ElfStepperIndicator` | The numbered circle; completed steps show a check. The `default` slot replaces the content. |
| `ElfStepperTitle` | The step name. Renders a `span`; required, because it is the accessible name of the trigger. |
| `ElfStepperDescription` | Optional helper text. Renders a `span`. |
| `ElfStepperSeparator` | The line to the next step; it fills with the primary colour once the step is completed. Leave it out of the last step. |

::callout{type="info" title="Descriptions"}
Keep `ElfStepperDescription` outside the trigger when you need more than a title (see the vertical example). Visible text inside a button that is not part of its name is flagged by accessibility checkers.
::

## Accessibility

- The root is a `group`; give it an `aria-label` that says what the steps are for (it defaults to "progress").
- The active item has `aria-current="true"`. Each trigger is a button named by its title and described by its description.
- A visually hidden live region announces "Step 2 of 3" whenever the step changes.
- With `linear`, steps more than one ahead of the current step are disabled, so they cannot be focused or selected.
- The step number is generated content and the indicator is hidden from assistive technology, so the accessible name is the title only.
- Transitions stop under `prefers-reduced-motion`. Triggers are at least 40px high.

| Key | Action |
| :-- | :-- |
| <kbd>Tab</kbd> | Moves focus into and out of the stepper. |
| <kbd>→</kbd> / <kbd>←</kbd> | Horizontal: moves focus to the next or previous step (mirrored in right-to-left). |
| <kbd>↓</kbd> / <kbd>↑</kbd> | Vertical: moves focus to the next or previous step. |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Selects the focused step. |

## Do and don't

| Do | Don't |
| :-- | :-- |
| Use short titles so every step fits on a phone. | Put long text in a horizontal stepper; use the vertical layout. |
| Name the stepper with `aria-label`. | Rely on the number alone to say what a step is. |
| Show the step content next to Back and Next buttons. | Use a stepper for peer views; use tabs instead. |
