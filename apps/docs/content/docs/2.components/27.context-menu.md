## Usage

```vue
<template>
  <ElfContextMenu>
    <ElfContextMenuTrigger as-child>
      <div tabindex="0" role="group" aria-label="Item card. Press Shift+F10 for actions.">
        Right-click here
      </div>
    </ElfContextMenuTrigger>
    <ElfContextMenuContent>
      <ElfContextMenuItem>Open</ElfContextMenuItem>
      <ElfContextMenuSeparator />
      <ElfContextMenuItem variant="destructive">Delete</ElfContextMenuItem>
    </ElfContextMenuContent>
  </ElfContextMenu>
</template>
```

`ElfContextMenu` is built on the Reka UI `ContextMenu` primitive. It has the same parts as the [Dropdown Menu](/docs/components/dropdown-menu) (`Item`, `CheckboxItem`, `RadioGroup`, `RadioItem`, `Label`, `Group`, `Separator`, `Shortcut`, `Sub`, `SubTrigger`, `SubContent`) and the same styles: both are built from the helpers exported by the dropdown menu module, so this component depends on it in the registry. The differences are the trigger and the position: the menu opens at the pointer instead of below a button.

| Part | Purpose |
| :-- | :-- |
| `ElfContextMenu` | Holds `modal` and the long-press delay. Renders no element. |
| `ElfContextMenuTrigger` | The area that has the menu. Renders a `span` by default; use `as-child` to make your own element the area. `disabled` turns the menu off. |
| `ElfContextMenuContent` and the item parts | As in the Dropdown Menu. |

A context menu is a shortcut, never the only way to reach an action: the same actions must be available elsewhere (a button, a toolbar or a dropdown menu), because most people never right-click and touch users must long-press. Make the area keyboard reachable (`tabindex="0"` plus a role and a name that mentions the shortcut) so that <kbd>Shift</kbd> + <kbd>F10</kbd> or the <kbd>ContextMenu</kbd> key work.

### Mobile

On touch screens the menu opens with a long press (700 ms by default, `pressOpenDelay`). Item rows are 40px high below the `md` breakpoint, and the menu stays inside the viewport.

## Accessibility

- Follows the WAI-ARIA [Menu](https://www.w3.org/WAI/ARIA/apg/patterns/menu/) pattern with the same roles as the Dropdown Menu: `role="menu"` and `menuitem`, `menuitemcheckbox` or `menuitemradio` rows.
- Keyboard: a focused trigger area opens the menu with <kbd>Shift</kbd> + <kbd>F10</kbd> or the <kbd>ContextMenu</kbd> key (the browser sends the `contextmenu` event). Focus moves into the menu and returns to the area on close.
- The area needs a role and an accessible name when it is focusable; say in the name that a menu is available.
- While open, the page behind is hidden from assistive technology and inert (`modal`).

| Key | Action |
| :-- | :-- |
| <kbd>Shift</kbd> + <kbd>F10</kbd> / <kbd>ContextMenu</kbd> | On the focused area, opens the menu. |
| <kbd>ArrowDown</kbd> / <kbd>ArrowUp</kbd> | Moves to the next or previous item. |
| <kbd>Home</kbd> / <kbd>End</kbd> | Focuses the first or last item. |
| Typing | Typeahead: focuses the next item whose text starts with the typed characters. |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Activates the item and closes the menu. |
| <kbd>ArrowRight</kbd> / <kbd>ArrowLeft</kbd> | Opens a sub menu, or closes it and returns to its trigger. |
| <kbd>Escape</kbd> | Closes the menu and returns focus to the area. |

## Do and don't

| Do | Don't |
| :-- | :-- |
| Offer the same actions in a visible control as well. | Hide an action behind right-click only. |
| Make the area focusable and named so the keyboard can open the menu. | Attach it to a non-focusable element and forget keyboard users. |
| Keep it short; use sub menus for secondary actions. | Replace the native menu on text fields, where people expect copy and paste. |
