## Usage

```vue
<ElfAlert variant="warning">
  <ElfAlertTitle>Battery 3 is below 12 V</ElfAlertTitle>
  <ElfAlertDescription>Swap it for a charged battery before the next match.</ElfAlertDescription>
</ElfAlert>
```

Reka UI has no alert primitive, so `ElfAlert` is composed from native elements: a container with an icon and a content column that holds `ElfAlertTitle` and `ElfAlertDescription`. An alert is a message, not a dialog or a toast: it stays in the page flow until the page removes it, and it takes no focus.

## Examples

### Variants

`default`, `success`, `warning` and `destructive`. Each has its own icon, a tinted surface and a colored border; the title carries the meaning in words, so color is never the only cue.

### Announced when it appears

An alert that is inserted into the page after it has loaded is announced by screen readers because of its live region role. Use `v-if` to add it on demand.

## Accessibility

- The `role` prop picks the live region behavior: `alert` is assertive and interrupts the user, `status` is polite, and `none` removes the role. It defaults to `alert` for the `destructive` variant and `status` for the others.
- **Only content added after the page loaded is announced.** A role on an alert that is already in the initial HTML is not read out as news; use `role="none"` for static notices so that the role does not add noise.
- Do not move focus to an alert, and do not make it auto-dismiss: users need time to read it. If it can be dismissed, give the button a clear accessible name.
- The icon is `aria-hidden`. State the severity in the title ("Save failed"), not in the icon or color alone.
- Text and border colors use the theme tokens `destructive`, `success` and `warning` over their tinted surfaces and meet 4.5:1 contrast in every theme.

| Key | Action |
| :-- | :-- |
| <kbd>Tab</kbd> | An alert is not interactive and is skipped. Links and buttons inside it are reached in order. |

## Do and don't

| Do | Don't |
| :-- | :-- |
| Write a short title that names the event and a description with the next step. | Use only an icon or a color to say what happened. |
| Use `destructive` for errors that block the user and `warning` for risks. | Use `destructive` for every notice. |
| Insert a live alert after the user's action (save, submit). | Give every alert on a page `role="alert"`; they would all be read out at once. |
| Keep it in the flow near the content it concerns. | Use an alert for a confirmation that needs an answer; use a dialog. |
