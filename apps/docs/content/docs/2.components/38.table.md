## Usage

```vue
<script setup lang="ts">
const members = [
  { name: 'Ayşe Demir', role: 'Software' },
  { name: 'Mert Kaya', role: 'Mechanical' },
]
</script>

<template>
  <ElfTable caption="Team members">
    <ElfTableHeader>
      <ElfTableRow>
        <ElfTableHead>Name</ElfTableHead>
        <ElfTableHead>Role</ElfTableHead>
      </ElfTableRow>
    </ElfTableHeader>
    <ElfTableBody>
      <ElfTableRow v-for="m in members" :key="m.name">
        <ElfTableCell>{{ m.name }}</ElfTableCell>
        <ElfTableCell>{{ m.role }}</ElfTableCell>
      </ElfTableRow>
    </ElfTableBody>
  </ElfTable>
</template>
```

`ElfTable` is composed from native table elements: there is no Reka UI primitive for a plain table, and none is needed, because the browser already provides the semantics. The component adds the styling, a scroll container and a few optional behaviors. The parts map one to one to the HTML elements, so a data table (sorting, selection, pagination) can be composed on top of them.

| Part | Element | Purpose |
| :-- | :-- | :-- |
| `ElfTable` | `div` > `table` | Scroll container and the table. Takes the required `caption`, `density`, `stackOnMobile`, `stickyHeader`. |
| `ElfTableCaption` | `caption` | Rendered for you from the `caption` prop; use it only inside the `caption` slot to customise the markup. |
| `ElfTableHeader` | `thead` | Header rows. |
| `ElfTableBody` | `tbody` | Data rows. |
| `ElfTableFooter` | `tfoot` | Totals or summaries. |
| `ElfTableRow` | `tr` | A row. `selected` sets `data-state="selected"`. |
| `ElfTableHead` | `th` | Column header with `scope="col"`. `sort` sets `aria-sort`. |
| `ElfTableCell` | `td` | A cell. `label` names the column in stacked mode. |

The caption is required. It is the table's accessible name and a visible title; pass `caption-hidden` when a nearby heading already says the same thing, and the caption is hidden visually but still announced.

### Mobile

Wide tables scroll sideways inside their container, which is the safe default for data that must stay in columns. With `stack-on-mobile`, each row becomes a card below the `sm` breakpoint (640px) and every cell shows `label: value`; give each `ElfTableCell` a `label`. The header row stays in the accessibility tree and is hidden visually. Changing `display` on table elements can drop their table semantics in some browsers, so stacked tables add explicit `table`, `rowgroup`, `row`, `columnheader` and `cell` roles.

### Building a data table

Put a button inside `ElfTableHead` and set its `sort` prop to `ascending`, `descending` or `none`; assistive technology announces the sort state from `aria-sort`. The sortable example shows the pattern. Keep the sort logic in your component (or in a table library); `ElfTable` stays presentational.

## Accessibility

- Follows the WAI-ARIA [Table](https://www.w3.org/WAI/ARIA/apg/patterns/table/) pattern with native `table`, `caption`, `th scope="col"` and `td` elements. Use tables for tabular data only.
- The `caption` is required and names the table. A table without a name is announced as just "table".
- When the table is wider than its container, the container becomes a focusable `region` named by the caption so keyboard users can scroll it with the arrow keys. It leaves the tab order again when everything fits.
- Sortable columns expose `aria-sort`; the sort control is a real button inside the header cell.
- A table is read-only content, so it has no keyboard interaction of its own. Interactive content in cells (buttons, links, checkboxes) is reached with <kbd>Tab</kbd> in reading order.

| Key | Action |
| :-- | :-- |
| <kbd>Tab</kbd> | Moves to the scroll container when the table overflows, then to the interactive content inside the cells. |
| <kbd>ArrowLeft</kbd> / <kbd>ArrowRight</kbd> | Scrolls the focused container horizontally. |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Activates a sort button in a header cell. |

Screen readers have their own table navigation commands (for example <kbd>Ctrl</kbd> + <kbd>Alt</kbd> + arrow keys in NVDA and JAWS); they work because the markup is native.

## Do and don't

| Do | Don't |
| :-- | :-- |
| Give every table a caption. | Leave the caption out because a heading is nearby; hide it instead. |
| Use `stack-on-mobile` for lists of records with a few short columns. | Stack tables whose meaning depends on comparing columns. |
| Keep the cell text short and right-align numbers. | Use a table to lay out a page. |
