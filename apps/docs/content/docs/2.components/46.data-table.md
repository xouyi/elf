## Installation

::component-install{component="data-table"}
::

The headless logic comes from [`@tanstack/vue-table`](https://tanstack.com/table), a regular dependency of `{{pkg}}`, so installing the package brings it along. You import nothing from TanStack for the common case: `createDataTableColumnHelper` and the `DataTable*` types are re-exported. Bundlers only include it when you use the data table.

## Usage

Describe the columns once (outside the template, or in a `computed`, but never inline in the template), then pass the rows.

```vue
<script setup lang="ts">
import { createDataTableColumnHelper } from '{{pkg}}'

interface Member {
  id: string
  name: string
  team: string
}

const col = createDataTableColumnHelper<Member>()
const columns = [
  col.accessor('name', { header: 'Name' }),
  col.accessor('team', { header: 'Team' }),
]
const members: Member[] = [
  { id: 'm1', name: 'Ayşe Demir', team: 'Software' },
  { id: 'm2', name: 'Mert Kaya', team: 'Mechanical' },
]
</script>

<template>
  <ElfDataTable caption="Team members" :columns="columns" :data="members" row-key="id" />
</template>
```

`caption` is required, as for [Table](/docs/components/table), which renders the markup. Every column with an accessor is sortable by default; set `enableSorting: false` on a column to opt out. The first click on a number column sorts the largest value first, the TanStack default for numbers.

### State

Each piece of state is a `v-model` and works uncontrolled too, so bind only what you need.

| Model | Value | Notes |
| :-- | :-- | :-- |
| `v-model:sorting` | `[{ id: 'name', desc: false }]` | Column ids; the order of the array is the sort priority. |
| `v-model:selection` | `{ m1: true }` | Keyed by `rowKey`. Needs `selectable`. |
| `v-model:columnVisibility` | `{ team: false }` | A missing id is visible. |
| `v-model:pagination` | `{ pageIndex: 0, pageSize: 10 }` | Zero-based. Without it the table starts from `pageSize`. |
| `v-model:globalFilter` | `'ayşe'` | The search text. Needs `searchable` to show the input, or bind your own. |

Give rows a stable `rowKey` (a key of the row, or a function) whenever you use selection or reorder the data; the default is the row index.

### Cells and headers

Render a cell with the `cell-<columnId>` slot, which receives `value`, `row` (a TanStack row; `row.original` is your object), `column` and `cell`. The `header-<columnId>` slot replaces the label of a header; for sortable columns it stays inside the sort button.

```vue
<ElfDataTable caption="Team members" :columns="columns" :data="members" row-key="id">
  <template #cell-team="{ value }">
    <ElfBadge variant="secondary">{{ value }}</ElfBadge>
  </template>
</ElfDataTable>
```

Columns can also render by themselves with a `cell` function in the column definition; the slots are the simplest way to use Vue components.

### Server-driven mode

`manual-sorting`, `manual-filtering` and `manual-pagination` hand each step to your server: the table stops sorting, filtering and slicing `data`, shows exactly the rows you pass and only reports what the user asked for through the models. Pass the total as `row-count` so the pages are counted. When the sort or the search changes in `manual-pagination` mode the table moves back to the first page for you. Watch the models, fetch, and set `loading` meanwhile (see the example below).

### Narrow screens

Wide tables scroll sideways inside their container and never widen the page. Add `stack-on-mobile` to show each row as a card below 640px instead (see [Table](/docs/components/table#mobile)); the cell labels come from the column headers. The pagination switches to a compact previous/next bar below `sm`.

### Translation

Pass any subset of the texts through `labels`:

```vue
<ElfDataTable
  :labels="{ search: 'Ara', columns: 'Sütunlar', selectAll: 'Tüm satırları seç', selectRow: 'Satırı seç', emptyTitle: 'Sonuç yok', selected: (n, total) => `${total} satırdan ${n} seçili` }"
/>
```

## Examples

### Selection

`selectable` adds a checkbox column. The header checkbox selects the rows of the current page and is mixed when only some are selected; the footer counts the selected rows.

::component-preview{name="data-table-selection"}
::

### Search and column visibility

`searchable` shows an [Input](/docs/components/input) bound to `v-model:globalFilter`; `column-toggle` shows a [Dropdown Menu](/docs/components/dropdown-menu) of checkbox items that stays open while you choose. Put your own buttons in the `actions` slot.

::component-preview{name="data-table-filtering-and-columns"}
::

### Loading

While `loading` is set the rows are replaced by skeleton rows (`loading-rows` of them), the table gets `aria-busy` and a screen reader hears "Loading". Use the `loading` slot to replace the skeleton rows.

::component-preview{name="data-table-loading"}
::

### Empty

With no rows the table shows an [Empty](/docs/components/empty) state. Replace it with the `empty` slot, for example to add a call to action.

::component-preview{name="data-table-empty"}
::

### Server-side

Sorting, search and pages go through a fake asynchronous fetch. The models drive the request and `row-count` comes from the response.

::component-preview{name="data-table-server-side"}

## Accessibility

- Built on [Table](/docs/components/table): native `table`, `caption`, `th scope="col"` and `td` elements, following the WAI-ARIA [Table](https://www.w3.org/WAI/ARIA/apg/patterns/table/) pattern.
- Each sortable header holds a real `button` inside the `th`, and the `th` carries `aria-sort` (`ascending`, `descending` or `none`). Columns that cannot be sorted have no button and no `aria-sort`.
- The selection checkboxes are named "Select all rows" and "Select row" (translate them with `labels`). Selected rows get `data-state="selected"` and the footer states the count in text.
- While loading, the table is `aria-busy` and a polite status says "Loading"; the skeleton rows are hidden from assistive technology.
- The column menu is a [Dropdown Menu](/docs/components/dropdown-menu) of `menuitemcheckbox` items. The search input is labelled "Search".
- Pagination is a labelled `nav`; the current page has `aria-current="page"`.
- When the table is wider than its container, the container becomes a focusable region so keyboard users can scroll it.

| Key | Action |
| :-- | :-- |
| <kbd>Tab</kbd> | Moves through the toolbar, the header buttons, the row checkboxes and the pagination in reading order. |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | On a header button: sorts the column (ascending, descending, then none). On a checkbox: toggles the row. |
| <kbd>Shift</kbd> + click | On a header button: adds the column to a multi-column sort. |
| <kbd>Enter</kbd> / <kbd>Space</kbd> / <kbd>ArrowDown</kbd> | On the Columns button: opens the menu. |
| <kbd>ArrowDown</kbd> / <kbd>ArrowUp</kbd> | In the Columns menu: moves between columns. |
| <kbd>Space</kbd> / <kbd>Enter</kbd> | In the Columns menu: shows or hides the column and keeps the menu open. |
| <kbd>Escape</kbd> | Closes the Columns menu and returns focus to its button. |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | On a page button: goes to that page. |

## Do and don't

| Do | Don't |
| :-- | :-- |
| Define `columns` once, outside the template. | Create the column array inline in the template; it is rebuilt on every render. |
| Pass a stable `row-key` when rows are selected or reordered. | Rely on the row index for selection of data that changes. |
| Use the `manual-*` props together with `row-count` for big data sets. | Load every row and filter in the browser when the table has thousands of rows. |
| Keep the text of cells short and put the value in `cell-<key>` slots when it needs markup. | Put interactive controls in a header slot that compete with the sort button. |
