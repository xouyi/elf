The `@xouyi/elfui` package ships a small command line tool (the installed binary is called `elfui`). It has no runtime dependencies, runs on Node 22+ and Bun, and always installs packages with the package manager it detects in your project (Bun when there is no lockfile).

```bash
bunx @xouyi/elfui@latest <command>
```

Once `@xouyi/elfui` is a dependency, `bunx elfui <command>` (or `bunx @xouyi/elfui <command>`) runs the installed version. The examples below use the scoped form, which also works outside a project.

## Commands

| Command | What it does |
| :-- | :-- |
| `init` | Sets up ElfUI in a Nuxt 4 or Vite + Vue project. |
| `add <component...>` | Copies components (and everything they depend on) into your project. |
| `list` | Shows every component in the registry. |
| `diff <component...>` | Compares your local copy of a component with the registry version. |
| `--version`, `--help` | Print the version or the usage. |

### init

```bash
bunx @xouyi/elfui@latest init
bunx @xouyi/elfui@latest init --theme nova --yes
```

1. Detects Nuxt or Vite + Vue and the package manager.
2. Installs `@xouyi/elfui`, `tailwindcss` and `@tailwindcss/vite` (plus `typescript@5` as a dev dependency) when they are missing.
3. Nuxt: adds `@xouyi/elfui/nuxt` to `modules`, the `elfui` theme option (the config key keeps the short name), the main CSS file and the Tailwind Vite plugin. Vite: adds `tailwindcss()` to `vite.config`.
4. Creates or patches the main CSS so it imports `tailwindcss` and `@xouyi/elfui/styles.css` (plus the theme file with Vite), and sets `data-theme` on `<html>` for non-default themes.

`init` is idempotent: running it twice changes nothing the second time. If your config has a shape it does not recognize (for example `export default makeConfig()`), it changes nothing and prints the manual steps instead.

### add

```bash
bunx @xouyi/elfui add button dialog
bunx @xouyi/elfui add field --path components/ui --overwrite
bunx @xouyi/elfui add button --registry ./registry/r
```

Copies each component and, recursively, its `registryDependencies` (the `cn()` helper in `lib/utils`, sibling components). Imports are rewritten to your project: `@/...` when your tsconfig defines that alias, `~/...` in Nuxt, relative paths otherwise. Missing npm dependencies are installed. The CLI never overwrites a file that differs from the registry unless you pass `--overwrite`; it keeps yours and tells you. An existing `lib/utils` is left alone because projects often have their own `cn`.

### list and diff

```bash
bunx @xouyi/elfui list
bunx @xouyi/elfui diff button
```

`diff` prints a unified diff between your copy and the registry, or "Everything matches".

## Options

| Option | Applies to | Description |
| :-- | :-- | :-- |
| `--theme <elf\|nova\|elfwood>` | `init` | Theme to configure. Default `elf`. |
| `--path <dir>` | `add`, `diff` | Components directory below `src` (or `app` in Nuxt). Default `components/ui`. |
| `--overwrite` | `add` | Replace files that differ from the registry. |
| `--registry <url\|dir>` | `add`, `list`, `diff` | Registry base URL or local directory. Env: `ELFUI_REGISTRY`. |
| `--no-install` | `init`, `add` | Do not run the package manager. |
| `--dry-run` | all | Print what would change without writing files. |
| `--cwd <dir>` | all | Run as if started in `<dir>`. |
| `--json` | `list` | Machine-readable output. |
| `-y`, `--yes` | all | Accept defaults and never prompt. |

## The registry

Components come from static JSON files at `https://xouyi.github.io/elfUI/r/` (the default). Each file lists the component's sources, its npm `dependencies` and its `registryDependencies`. They are the same files the [shadcn-vue CLI](/docs/getting-started/registry) reads. Point `--registry` (or `ELFUI_REGISTRY`) at another URL, or at a local directory such as a checkout's `registry/r`, to use a mirror or work offline.

## Copying or using the package?

| | Package (`import ... from '@xouyi/elfui'`) | Copy (`elfui add`) |
| :-- | :-- | :-- |
| Where the code lives | `node_modules` | Your repository |
| Updates | `bun update @xouyi/elfui` | `elfui diff`, then `add --overwrite` |
| Customization | Props, classes, tokens | Edit the source |

You can mix both: use the package everywhere and copy a single component you need to fork. `init` is useful in either case, because the theme CSS and Tailwind setup are the same.
