---
title: useElfTheme
description: Switch themes in one line. A composable with module-wide defaults, SSR-safe persistence in a cookie or localStorage, and no flash.
---

`useElfTheme()` reads and sets the theme that [Theming](/docs/getting-started/theming) selects with `data-theme` on `<html>`. It is exported from `{{pkg}}` and auto-imported in Nuxt.

## Quick start

### Nuxt

One line in `nuxt.config.ts` lists the themes you switch between. Everything else (cookie, server rendering, no flash) is done by the module.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['{{pkg}}/nuxt'],
  elfui: { theme: 'elf', themes: ['nova', 'elfwood'] }, // persist: 'cookie' is the default
})
```

Then call the composable with no arguments, anywhere:

```vue
<script setup lang="ts">
const { theme, themes, setTheme, toggle } = useElfTheme()
</script>

<template>
  <ElfButton variant="outline" @click="toggle">Theme: {{ theme }}</ElfButton>
  <ElfButton v-for="name in themes" :key="name" @click="setTheme(name)">{{ name }}</ElfButton>
</template>
```

The module adds a plugin that reads the cookie on the server, so the first HTML already carries the visitor's `<html data-theme>` (no flash), validates the value (an unknown cookie is ignored) and gives `useElfTheme()` the module's themes, default and persistence. Module options:

| Option | Default | Description |
| :-- | :-- | :-- |
| `theme` | `'elf'` | Default theme. |
| `themes` | selected theme only | Further themes to bundle and to switch between. The list `useElfTheme().themes` returns is `themes`, with `theme` first unless you list it yourself. |
| `persist` | `'cookie'` | `'cookie'` (the server reads it), `'localStorage'` (a tiny inline script applies it before the first paint) or `false`. Prerendered sites (`nuxt generate`) cannot read a cookie at build time: the same inline script covers them. |

### Vite + Vue

Install the plugin once, then call the composable with no arguments:

```ts [src/main.ts]
import { createElfTheme } from '{{pkg}}'
import { createApp } from 'vue'
import App from './App.vue'

createApp(App)
  .use(createElfTheme({ themes: ['elf', 'nova', 'elfwood'], defaultTheme: 'elf', persist: 'localStorage' }))
  .mount('#app')
```

```vue [src/App.vue]
<script setup lang="ts">
import { useElfTheme } from '{{pkg}}'

const { theme, toggle } = useElfTheme()
</script>

<template>
  <button @click="toggle">Theme: {{ theme }}</button>
</template>
```

The plugin applies the stored choice before the first render. To also avoid a flash while the JavaScript bundle loads, put the boot script in `index.html` (it must list the same themes and use the same `persist` as the plugin, here the default `localStorage`):

```html [index.html]
<head>
  <script>
    try{var t=localStorage.getItem('elfui-theme');if(['elf','nova','elfwood'].indexOf(t)>-1)document.documentElement.dataset.theme=t}catch(e){}
  </script>
</head>
```

`elfThemeBootScript({ themes, storage, storageKey })` generates exactly this string, for build tools that inject it (for example `transformIndexHtml` in a Vite plugin).

`createElfTheme()` options: `themes` (default: the shipped themes), `defaultTheme` (default: the first theme), `persist` (`'localStorage'` by default, `'cookie'` or `false`), `storageKey` and `cookieMaxAge`.

## Drop-in switcher

`<ElfThemeSwitcher />` is a ready-made control that uses the same configuration: no code needed. See [Theme Switcher](/docs/components/theme-switcher).

## What it does

- `theme` is a read-only ref with the active name. Its type is the union of the accepted names (`'elf' | 'nova' | 'elfwood'` by default).
- `setTheme(name)` updates `theme`, sets `data-theme` on `<html>` and stores the choice when persistence is on. A name that is not accepted is ignored (and logged in development).
- `cycle()` activates the next theme in the list and wraps around. `toggle()` is the one-button version: with two themes it flips between them, with more it behaves like `cycle()`.
- State belongs to the Vue app, so two requests on a server never share a theme, and every component that calls `useElfTheme()` sees the same value.

## Options

Every option is optional. Without options the composable uses what the Nuxt module or `createElfTheme()` configured; an option you pass wins over that configuration.

| Option | Default | Description |
| :-- | :-- | :-- |
| `themes` | module or plugin themes, else `['elf', 'nova', 'elfwood']` | Accepted names. Pass your own list to add [custom themes](/docs/getting-started/theming); the name type is inferred. |
| `defaultTheme` | first of `themes` | Theme used until something else decides. With the Nuxt module this is `elfui.theme`. |
| `initial` | none | Theme to render first. On the server, pass the value read from the request cookie so that server and client agree. |
| `storage` | module or plugin `persist`, else `'none'` | `'localStorage'`, `'cookie'` or `'none'`. |
| `storageKey` | `'elfui-theme'` | localStorage key or cookie name. |
| `cookieMaxAge` | one year | Cookie lifetime in seconds. |
| `target` | `document.documentElement` | Element that carries `data-theme`. |

## Persist the choice without the module or plugin

The Nuxt `persist` option and `createElfTheme({ persist })` cover this. When you use neither, pick where the choice is kept per call:

```ts
useElfTheme({ storage: 'localStorage' }) // read on the client only
useElfTheme({ storage: 'cookie' })       // can also be read by the server
```

When the component mounts, the stored value (if it is an accepted name) replaces the current theme. Storage failures (private mode, blocked cookies) are caught: the theme still applies for the visit.

### Avoid the flash of the default theme

The stored value is applied after the page has loaded. To apply it before the first paint, put `elfThemeBootScript()` in the head. It returns a tiny inline script that sets `data-theme` from storage:

```ts
useHead({ script: [{ innerHTML: elfThemeBootScript({ storage: 'localStorage' }) }] })
```

Use the same `storage` and `storageKey` as in `useElfTheme`.

## Nuxt without the module defaults

The module does the following for you; you only need it by hand when you call `useElfTheme` with your own options. Read the cookie with `useCookie`, pass it as `initial`, and keep `<html data-theme>` in sync with `useHead`:

```vue
<script setup lang="ts">
const cookie = useCookie<string>('elfui-theme', { maxAge: 60 * 60 * 24 * 365, sameSite: 'lax' })
const { theme } = useElfTheme({
  defaultTheme: 'nova',
  initial: isElfTheme(cookie.value) ? cookie.value : undefined,
  storage: 'cookie',
})
useHead({ htmlAttrs: { 'data-theme': theme } })
</script>
```

## Server-side rendering

Nothing in the composable touches `document`, `window` or any storage on the server. During SSR `theme` is `initial` (or the default); the browser then adopts what the visitor stored when the component mounts. If you render the theme name in the page, pass `initial` so the first client render matches the server HTML, or you will see a hydration mismatch.

## Custom themes

```ts
const { theme, setTheme } = useElfTheme({ themes: ['ocean', 'forest'] as const, defaultTheme: 'ocean' })
setTheme('forest')   // typed: only 'ocean' | 'forest'
```

Define the matching `[data-theme='ocean']` token blocks as described in [Theming](/docs/getting-started/theming). In an app, list the custom names once in `createElfTheme({ themes: ['ocean', 'forest'] })` and call `useElfTheme()` with no arguments (the Nuxt module option `themes` takes the shipped theme names only).

## Accessibility

Changing the theme only swaps colors and radius; every theme must pass `bun run contrast`. A theme control must be a real button or a group of radio-style buttons with a visible name, and must show the current choice (`aria-pressed` or `aria-current`). The preference is yours to store: respect it, and do not change the theme without a user action.
